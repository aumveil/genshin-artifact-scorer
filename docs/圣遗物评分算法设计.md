# 圣遗物评分算法设计

> 基于《圣遗物背景知识总结.md》设计，包含四个算法：单件圣遗物词条计算、角色圣遗物评分、圣遗物价值评估、圣遗物重塑价值评估。
> 约定：已录入角色圣遗物信息（含散件部位标记、有效词条、词条权值、5 部位副词条具体数值），且**默认主词条全对**。

## 一、输入数据模型

### 1.1 圣遗物（Artifact）

| 字段 | 说明 |
|------|------|
| slot | 部位：flower / plume / sands / goblet / circlet（花/羽/沙/杯/头） |
| set | 所属套装（如「绝缘之旗印」「昔日宗室之仪」），已穿戴件与新圣遗物均需录入；用于情况二同套装替换判定 |
| mainStat | 主词条（默认已正确，评估算法中可选校验） |
| level | 当前等级（0~20 整数），用于计算剩余未解锁强化次数；满级 = 20 |
| substats | 副词条集合，每项为 `(stat, value, activated)`；stat 为 10 种副属性之一，value 为显示值（百分比词条用百分数，如 3.5 表示 3.5%），**activated 标记该词条是否已激活**（未激活 = 待激活，4 级强化解锁） |

> **3 初始 / 4 初始录入约定**：5★ 圣遗物初始最多 4 条副属性，其中最多 1 条未激活。
> - **4 初始**：substats 4 条全部 `activated = true`（0 级即可录入 4 条）。
> - **3 初始**：0 级录入 3 条激活 + 1 条**待激活**（`activated = false`），例如：攻击力+4.1%（激活）、生命值+4.7%（激活）、充能+6.5%（激活）、防御力+19（待激活）。**待激活词条的属性和数值均由用户录入确定**（如防御力 +19），4 级强化解锁后直接生效，无需 roll 假设。
> - 未激活词条**不参与** currentScore 计算（算法一），但**参与**潜力计算（算法三，按录入数值计入）。

### 1.2 角色配置（RoleConfig）

| 字段 | 说明 |
|------|------|
| artifacts | 5 个部位当前已装备的圣遗物 |
| looseSlot | 散件部位（情况一「作为散件」评估的比较基准，如 4+1 套装的第 5 件）；为空 = 无散件（如 5 件全套装），此时自由位由 `freeSlots` 按「冗余位」自动识别（见 4.1） |
| effectiveStats | 有效词条集合（该角色需要的副属性） |
| weights | 词条权值表 `w(stat)`，仅对有效词条定义（如暴击率 1.0、爆伤 1.0、大攻击 0.8） |
| erRequirement | 元素充能效率需求阈值（如 180%），充能词条超过阈值部分无效 |
| currentER | 当前面板元素充能效率（直接录入，含基础 100% 及武器等全部来源） |

> 充能阈值说明：面板充能由用户直接录入（`currentER`）。超额部分按当量直接扣减；不足部分仅打标签提示，不扣分（见 3.4 节）。

### 1.3 核心常数

满挡单发最大值表 Umax（滚数当量基准）：

| 词条 | Umax |
|------|------|
| 暴击率 | 3.9% |
| 暴击伤害 | 7.8% |
| 攻击力百分比 | 5.8% |
| 生命值百分比 | 5.8% |
| 防御力百分比 | 7.3% |
| 元素精通 | 23 |
| 元素充能效率 | 6.5% |
| 攻击力 | 19 |
| 生命值 | 299 |
| 防御力 | 23 |

角色评分的满分基准不采用固定常数，而是由算法二根据角色配置（有效词条、权值、主词条）动态计算「完美词条数」，见 3.2 节。

强化相关常数（算法四使用）：

| 常数 | 值 | 说明 |
|------|-----|------|
| ROLL_AVG | 0.85 | 单次强化的数值档位期望：70% / 80% / 90% / 100% 四档等概率，期望恰为 0.85；档位与强化落点相互独立 |
| DUST_COST | 花/羽 1 枚、沙/杯/头 2 枚 | 启圣之尘单次重塑消耗；圣言解明进度按尘数积累，各部位终保底所需总尘相同 |

## 二、算法一：单件圣遗物词条计算

### 2.1 目标

给定一件圣遗物与角色配置，计算该圣遗物的**加权有效词条数**（滚数当量 × 权值），作为单件质量的核心度量。

### 2.2 公式

对圣遗物 S 的每条**已激活**副词条 `(stat, value)`（`activated = true`）：

1. 滚数当量（无量纲）：`rolls(stat, value) = value / Umax(stat)`
   - 含义：该词条相当于多少个「满挡单发」；例如暴击率 3.5% → 3.5 / 3.9 ≈ 0.897。
2. 单条加权得分：若 `stat ∈ effectiveStats`，得 `rolls × w(stat)`；否则得 `0`。
3. 单件总分：`score(S) = Σ rolls(stat, value) × w(stat)`（仅有效词条贡献）。

> 未激活（待激活）词条不参与计算——尚未生效，不贡献 currentScore。

### 2.3 伪代码

```
function calcArtifactScore(S, role):
    total = 0
    for (stat, value, activated) in S.substats:
        if not activated:                    # 待激活词条跳过
            continue
        if stat in role.effectiveStats:
            total += (value / UMAX[stat]) * role.weights[stat]
    return total
```

### 2.4 示例

角色有效词条：暴击率(1.0)、爆伤(1.0)、大攻击(0.8)、精通(0.6)。一件花：

| 副词条 | 显示值 | 当量 | 权值 | 加权分 |
|--------|--------|------|------|--------|
| 暴击率 | 7.4% | 7.4/3.9 ≈ 1.897 | 1.0 | 1.897 |
| 爆伤 | 14.6% | 14.6/7.8 ≈ 1.872 | 1.0 | 1.872 |
| 大攻击 | 10.5% | 10.5/5.8 ≈ 1.810 | 0.8 | 1.448 |
| 精通 | 42 | 42/23 ≈ 1.826 | 0.6 | 1.096 |

单件得分 ≈ **6.31**（加权有效词条数）。

## 三、算法二：角色圣遗物评分

### 3.1 目标

以**客观完美态**为满分基准：根据角色配置计算每个部位的「完美词条数」作为满分分母，再用角色当前实际加权词条数 ÷ 完美词条数得到 **0~100 分**。满分随角色变化，而非人为设定常数。

### 3.2 每部位完美词条数

一个部位的完美状态 = 初始副属性全部满挡有效 + 5 次强化全部满挡且落在有效词条上。

```
perfect(slot) = init(slot) + 5 × maxW(slot)
```

其中：

- **可用有效词条集**：`E(slot) = effectiveStats − { mainStat(slot) }`
  - 依据「主副词条不重复原则」：若主词条是有效词条（如杯主词条为攻击力百分比），该词条不能再出现在副词条中，需从有效词条中扣除。
- **init(slot)**：`E(slot)` 中权值最高的前 `min(4, |E(slot)|)` 条权值之和
  - 一件圣遗物最多 4 条副属性，因此最多计 4 条有效词条；
  - 每条按「初始满挡单发 = 1 当量 × 权值」计。
- **maxW(slot)**：`E(slot)` 中最高词条权值
  - 5 次强化按最优分配计（全部落在权值最高的词条上、每次满挡 1 当量）；
  - 当所有权值 ≤ 1 时，`5 × maxW = 5`，与直观「强化 5 次 +5」一致。

> 补充：若某部位有效词条超过 4 种，仅取权值最高的前 4 条，其余不计入（副词条上限 4 条）。

### 3.3 角色评分

1. 当前实际加权词条数：`total = Σ calcArtifactScore(artifact_slot, role)`（5 部位）
2. 完美总词条数：`perfectTotal = Σ perfect(slot)`（5 部位）
3. **充能阈值修正**（见 3.4）：
   - 超额：`excessRolls = max(0, (currentER − erRequirement) / 6.5%)`，按当量直接扣减
   - 修正后总分：`adjustedTotal = total − excessRolls × w(充能)`
   - 不足：`currentER < erRequirement` 时打标签提示，不扣分
4. 百分制评分：`percent = max(0, adjustedTotal / perfectTotal × 100)`
   - 满分对应完美状态，天然 ≤ 100；充能惩罚过大时**封底 0 分**，避免负分误导。

### 3.4 充能阈值修正

元素充能效率是「达标型」属性：

- **超额**（面板 > 需求）：超出部分的词条完全无效，按当量**直接全扣**（不区分超额来自圣遗物还是武器，全部记为该角色充能溢出浪费）。
  - 超额当量：`excessRolls = (currentER − erRequirement) / 6.5%`
  - 扣减得分：`penalty = excessRolls × w(充能)`（若充能非有效词条，w 取 0，不扣）
  - 例：需求 180%、面板 200% → 超额 20% → 20 / 6.5 ≈ 3.1 词条 → 评分扣除 3.1 × w(充能)。
- **不足**（面板 < 需求）：不扣分（词条仍在帮助接近阈值），但输出标签提示，如「充能不足，缺 30%」，通过 UI 视觉效果（如黄色警示标签）体现。

### 3.5 伪代码

```
function calcPerfect(slot, role):
    E = role.effectiveStats - { role.artifacts[slot].mainStat }
    top = 取 E 中权值最高的前 min(4, |E|) 条
    init = Σ_{e in top} role.weights[e]
    maxW = max(role.weights[e] for e in E)     # 若 E 为空则 maxW = 0
    return init + 5 * maxW

function calcEnergyPenalty(role):
    excess = max(0, (role.currentER - role.erRequirement) / 6.5%)
    wER = role.weights.get(元素充能效率, 0)    # 非有效词条则权值为 0
    return excess * wER                        # 超额当量 × 权值，直接全扣

function calcCharacterScore(role):
    total = 0
    perfectTotal = 0
    for slot in [flower, plume, sands, goblet, circlet]:
        total += calcArtifactScore(role.artifacts[slot], role)
        perfectTotal += calcPerfect(slot, role)

    adjustedTotal = total - calcEnergyPenalty(role)

    tags = []
    if role.currentER < role.erRequirement:
        tags.append(f"充能不足，缺 {role.erRequirement - role.currentER}%")

    percent = max(0, adjustedTotal / perfectTotal * 100)
    return { words: total, adjustedWords: adjustedTotal,
             perfect: perfectTotal, percent: percent, tags: tags }
```

### 3.6 示例（与需求方例子一致）

角色有效词条：暴击率(1.0)、暴击伤害(1.0)、攻击力百分比(0.5)；主词条：花=生命值、羽=攻击力、沙=攻击力百分比、杯=火伤、头=暴击伤害。

| 部位 | 主词条 | 占用有效词条？ | E(slot) | init | maxW | 完美词条数 |
|------|--------|--------------|---------|------|------|-----------|
| 花 | 生命值（非有效） | 否 | 暴击1 + 爆伤1 + 大攻0.5 | 2.5 | 1.0 | 2.5 + 5 = 7.5 |
| 羽 | 攻击力（数值，非有效） | 否 | 2.5 | 2.5 | 1.0 | 7.5 |
| 沙 | 攻击力百分比（有效0.5） | 是 | 暴击1 + 爆伤1 | 2.0 | 1.0 | 2.0 + 5 = 7.0 |
| 杯 | 火伤（非有效） | 否 | 2.5 | 2.5 | 1.0 | 7.5 |
| 头 | 暴击伤害（有效1.0） | 是 | 暴击1 + 大攻0.5 | 1.5 | 1.0 | 1.5 + 5 = 6.5 |

- `perfectTotal = 7.5 + 7.5 + 7.0 + 7.5 + 6.5 = 36`
- 若当前 `total = 25` → `percent = 25 / 36 × 100 ≈ 69.4` 分 ✓

## 四、算法三：圣遗物价值评估（含强化潜力）

### 4.1 目标

给定一件**新圣遗物**（已满级或未满级），判断它相对于角色当前已装备的圣遗物是否有价值。按需求：**不局限于散件**，评估新圣遗物的一切潜在使用方式；主词条默认全对。

三种使用方式（情况一 / 情况一′ / 情况二）：

| 情况 | 适用条件 | 比较对象 | 评估问题 |
|------|---------|---------|---------|
| 情况一：作为散件 | 新圣遗物部位 = 角色散件部位（looseSlot） | 当前散件 | 是否值得**替换散件**（满级）/ **强化**（未满级） |
| 情况一′：作为自由件 | 新圣遗物部位 ∈ 自由位，且角色**未设置** looseSlot（无散件 / 全套装） | 该部位当前件 | 同上（该部位是冗余件，替换后不损失套装效果） |
| 情况二：作为套装件 | 存在同部位、同套装（set 相同）、同主词条的已穿戴件 | 该已穿戴件 | 是否值得**替换同套装件** |

**自由位（冗余位）判定**（`freeSlots`）：角色当前可换成异套件而**不损失套装效果**的部位。

- `looseSlot` 已设置 → 自由位 = 该部位（仅一个，语义与旧版完全一致）。
- 「未设置」含 `null` / `undefined` / 空串 `""` 三种写法（校验层把空串与 null 同为合法的「无散件」值），三者行为完全一致（`hasLooseSlot` 判定）。
- `looseSlot` 为空（无散件 / 全套装）→ 部位 `S` 是自由位 ⟺ 除 `S` 外其余 4 件均已录入且**同属一套**：
  - 5 件全同套 → **5 个部位全为自由位**：原神无 5 件套效果，任意一件都是冗余件，换掉后仍是 4 件套，加成不受影响；
  - 4 件同套 + 1 件异套 → 仅那 1 件（真正的冗余件）；
  - 2+2+1 等分散套装 / 部位未录全 → 无自由位（换掉任一件都会破坏 2 件套或无法判定）→ 保守不评估。

> 因此 `looseSlot` 为空**不等于**「无可评估自由度」，而是「自由位由套装结构自动推断」——自由度最大的一种配装（5 件全同套）正属于此情形。
> 自由件与情况二共用同一被替换件与同一公式：新件为**同套同主词条**时优先记作情况二（标签更准确），不再重复出一条自由件结论。

- 情况一′是情况一在 `looseSlot` 为空时的自然推广（比较对象由「显式指定的散件」换成「按套装结构识别出的冗余件」），两者共用同一分支与同一判定口径。
- 情况二因「同部位 + 同套装 + 同主词条」替换，替换后套装构成完全不变，**依然满足忽略套装效果的评估前提**，与情况一判定口径一致。
- 三种情形的判定逻辑共用一个核心函数 `evaluateAgainst`（见 4.3），仅比较对象与适用条件不同。
- 最终汇总：任一情形「值得」→ 新圣遗物**有价值**。

核心思想：满级是潜力评估在 `remaining = 0` 时的特例；情况二与情况一′ 均是情况一的同构扩展（比较对象从显式散件换成同套装件 / 冗余件）。

### 4.2 潜力词条数计算

```
potentialScore(S) = currentScore(S) + pendingContrib(S) + max(0, remaining(S) − |pending(S)|) × maxW(slot)
```

- `currentScore(S) = calcArtifactScore(S, role)`：当前**已激活**副词条的加权词条数（待激活词条不计）
- `pending(S)`：待激活副词条集合（`activated = false`，3 初始的未激活词条，最多 1 条）
- `pendingContrib(S) = Σ_{(stat,value) ∈ pending} (value / Umax(stat)) × w(stat)`
  - 待激活词条的**属性和数值均由用户录入确定**（如待激活「防御力+19」），4 级解锁后直接生效，无需 roll 假设；
  - 当量 = 录入数值 ÷ Umax（与算法一相同口径）；
  - 例：待激活「防御力+19」→ 当量 = 19/23 ≈ 0.826；若防御力非有效词条，贡献 0；若有效且权值 0.5，贡献 0.413
- `remaining(S) = max(0, 5 − floor(S.level / 4))`：剩余**未解锁**的强化次数（满级为 0）
  - 强化词条在 4 / 8 / 12 / 16 / 20 级解锁，已解锁次数 = `min(5, floor(level/4))`；
  - 该公式对任意等级均成立（如 level=7 → 已解锁 1 次 → 剩 4 次；level=13 → 已解锁 3 次 → 剩 2 次）；
  - 其中 `|pending(S)|` 次用于解锁待激活词条（已计入 pendingContrib），剩余 `remaining − |pending|` 次为叠加（`max(0, ·)` 保护）
- `maxW(slot)`：该部位可用有效词条的最高权值（与算法二一致）
  - 每次叠加「最完美」= 满挡 1 当量，且砸在权值最高的有效词条上 → 每次 +maxW
- 满级时 `remaining = 0` 且无待激活词条 → `potentialScore = currentScore`，天然退化为替换评估（满级件的进一步价值路径——重塑，见算法四）

**兼容性说明（4 初始 / 3 初始 / 0 级）**：

| 圣遗物形态 | currentScore | pending | remaining | potentialScore |
|------|-------------|---------|-----------|----------------|
| 4 初始 · 0 级 | 4 条激活之和 | 无 | 5 | currentScore + 5×maxW |
| 3 初始 · 0 级 | 3 条激活之和 | 1 条待激活 | 5 | currentScore + pendingContrib(按录入数值) + 4×maxW |
| 3 初始 · 4 级 | 4 条（已解锁） | 无 | 4 | currentScore + 4×maxW |
| 满级 · 任一 | 全部激活 | 无 | 0 | currentScore |

> 3 初始圣遗物天然比 4 初始少一次叠加机会（解锁占用 1 次强化），潜力上限略低——与游戏实际一致（初始四优于初始三）。

### 4.3 评估流程

```
# —— 核心比较函数：新圣遗物 vs 指定被替换件（各情形共用）——
function evaluateAgainst(newArtifact, oldArtifact, role):
    # 潜力计算
    curScore   = calcArtifactScore(oldArtifact, role)         # 被替换件当前词条数
    newCurrent = calcArtifactScore(newArtifact, role)         # 新圣遗物当前（已激活词条）
    pending    = [s for s in newArtifact.substats if not s.activated]
    # 待激活词条按录入数值计当量（与算法一同口径），解锁后直接生效
    pendingContrib = Σ_{s in pending} (s.value / UMAX[s.stat]) * w(s.stat)
    remaining  = max(0, 5 - floor(newArtifact.level / 4))    # 剩余未解锁强化次数
    potential  = newCurrent + pendingContrib \
               + max(0, remaining - len(pending)) * maxW(newArtifact.slot)

    # 充能：新面板充能 = 当前面板 − 被替换件充能贡献 + 新圣遗物充能贡献（当前值）
    # 「已配置充能」＝ erRequirement 与 currentER 均非空（两字段在配置界面联动；
    #   任一为 null 即视为未配置 → 不做充能约束、也不输出提示）
    newER = role.currentER - ERContrib(oldArtifact) + ERContrib(newArtifact)
    erDelta = round2(newER - role.currentER)      # 面板充能变化量（2 位小数，抵消浮点尾差）

    # 充能提示（2026-09-29 二次口径变更）：同时看「这次替换对充能做了什么」与「替换后是否达标」
    #   Δ<0 且仍不足 → 充能不足，缺 X%      （lack，红）
    #   Δ>0 且仍不足 → 充能补足，还差 X%    （partial，黄）
    #   Δ>0 且已达标 → 充能满足             （met，绿）
    #   Δ=0 / 下降但仍达标 / 未配置充能 → 无提示
    tags, erTagLevel = [], None
    if erConfigured:
        gap = role.erRequirement - newER
        if erDelta < 0 and gap > 0:
            tags.append(f"充能不足，缺 {gap:.0f}%");  erTagLevel = "lack"
        elif erDelta > 0 and gap > 0:
            tags.append(f"充能补足，还差 {gap:.0f}%"); erTagLevel = "partial"
        elif erDelta > 0:
            tags.append("充能满足");                    erTagLevel = "met"

    # 判定（判定与评分解耦）
    diff = potential - curScore
    if newArtifact.level >= 20:
        # 满级：可评估替换 —— 【2026-09-29 口径变更】只看词条是否有提升；
        # 充能不足不再否决替换，仅由 tags 输出提示（见 §4.4「口径变更记录」）
        worthy = (diff > MIN_DIFF)
        verdict = "建议替换" if worthy else "不建议替换（词条无提升）"
    else:
        # 未满级：仅评估是否值得强化，不做替换判定
        worthy = (diff >= 0)
        verdict = worthy ? "值得强化" : "不值得强化"

    # 替换后评分（仅满级输出；按算法二口径重算，封底 0 分）
    if newArtifact.level >= 20:
        char = calcCharacterScore(role)              # 满分基准不受替换影响
        newTotal = char.words - curScore + potential # 满级时 potential == newCurrent
        newPenalty = max(0, (newER - role.erRequirement) / 6.5%) * w(充能)
        newAdjusted = newTotal - newPenalty
        newPercent = max(0, newAdjusted / char.perfect * 100)
    else:
        newPercent = null                            # 未满级不评估替换

    return {
        worthy: worthy, verdict: verdict,
        currentScore: curScore, newCurrentScore: newCurrent,
        potentialScore: potential, remaining: remaining,
        diffToCurrent: diff, newER: newER, tags: tags,
        newPercent: newPercent
    }

# —— 自由位（冗余位）判定：可换成异套件而不损失套装效果的部位 ——
function freeSlots(role):
    if role.looseSlot != null: return [role.looseSlot]      # 显式设置 → 仅该部位
    return [S for S in SLOTS if 除 S 外其余 4 件均已录入且同属一套]   # 未设置 → 按套装结构推断

# —— 主入口：评估新圣遗物的所有潜在使用方式 ——
function evaluateArtifact(newArtifact, role):
    results = []
    equipped = role.artifacts[newArtifact.slot]

    # 情况二：作为套装件（同部位、该部位是套装件而非散件、同套装、同主词条）
    isSetReplace = (equipped and newArtifact.slot != role.looseSlot
                    and newArtifact.set == equipped.set
                    and newArtifact.mainStat == equipped.mainStat)

    # 情况一/一′：作为散件（looseSlot 显式指定）或自由件（looseSlot 为空 → 冗余位自动识别）
    # 要求 部位 ∈ 自由位 且 主词条与被替换件一致；同套同主词条已由情况二覆盖 → 跳过避免重复评估
    if (not isSetReplace and equipped
        and newArtifact.mainStat == equipped.mainStat
        and newArtifact.slot in freeSlots(role)):
        r = evaluateAgainst(newArtifact, equipped, role)
        # isSetSwap（替换后散件位变套装件 → 角色失去散件）仅在显式配置了散件位时成立
        r.isSetSwap = (role.looseSlot != null) and isSetPiece(newArtifact, role)
        r.case = ("散件(变为套装件)" if r.isSetSwap else "散件") if role.looseSlot != null else "自由件"
        results.append(r)

    if isSetReplace:
        r = evaluateAgainst(newArtifact, equipped, role)
        r.case = "套装替换"; results.append(r)

    # 汇总：任一情况值得 → 有价值
    valuable = len(results) > 0 and any(r.worthy for r in results)

    return {
        valuable: valuable,
        summary: valuable ? "有价值" : (results.length == 0 ? "无适用场景" : "无价值"),
        results: results        # 情况一/一′/二 各自的结论
    }
```

> **判定与评分解耦**：判定回答「这件圣遗物本身值不值得换/强化」（**只看词条提升**；充能不足只提示、不否决——2026-09-29 口径变更，见 §4.4）；评分回答「替换后角色整体什么水平」（按算法二重算，含充能**超额**惩罚与**不足**标签）。两者独立，评分高低不否决判定结论。
> **各情形互不影响**：情况一/一′ 评估散件与自由件用途，情况二评估同套装替换用途，各自独立判定；汇总时任一值得即有潜力。

### 4.4 判定规则

核心函数 `evaluateAgainst` 的判定（各情形共用，`diff = potential − curScore`）：

| 圣遗物状态 | 条件 | 结论 |
|-----------|------|------|
| 满级（level=20） | diff > MIN_DIFF | **建议替换**（只看词条提升） |
| 满级 | diff ≤ MIN_DIFF | 不建议替换（词条无提升） |
| 未满级（level<20） | diff ≥ 0 | **值得强化** |
| 未满级 | diff < 0 | 不值得强化（最完美也无法超越） |

**充能提示与判定解耦**（不参与 worthy 判定，仅由 `tags` 输出；见 §4.4「充能提示分级」）：

| Δ = newER − currentER | 替换后是否达标 | 提示 | 级别 / 配色 |
|---|---|---|---|
| Δ < 0（充能降低） | 不足 | 充能不足，缺 X% | `lack` / 红 |
| Δ > 0（充能增加） | 仍不足 | 充能补足，还差 X% | `partial` / 黄 |
| Δ > 0（充能增加） | 达标 | 充能满足 | `met` / 绿 |
| Δ < 0（充能降低） | 达标 | 无提示 | — |
| Δ = 0（充能不变） | 任意 | 无提示 | — |
| 充能未配置（`null`） | — | 无提示 | — |

汇总规则（`evaluateArtifact`）：

| 情况组合 | 汇总结论 |
|---------|---------|
| 任一情况「值得」（worthy = true） | **有价值** |
| 所有情况都不值得 | 无价值 |
| 无任何适用情况（部位不是自由位或主词条不一致，且无同套装同主词条的已穿戴件） | 无适用场景 |

- `MIN_DIFF` 默认 0，可配置（如 0.5 过滤微小差异）。
- 满级替换只看词条提升（`diff > MIN_DIFF`）；**充能不足不否决替换**，仅输出提示标签（2026-09-29 口径变更，理由见下）。未满级仅判定是否值得强化，不做替换评估。
- 未满级采用「≥」：强化存在向上随机性，只要最完美情况有机会超越被替换件，就值得投入资源尝试。

#### 口径变更记录（2026-09-29）

> 当日两次变更，均按用户指示执行。变更一改「判定」，变更二改「提示」。

**变更一 · 充能不足不再否决替换**

**变更内容**：满级替换判定由「词条提升 **且** 替换后面板充能 ≥ 充能需求」改为**只看词条提升**；充能不足由「硬否决」改为「仅提示」——提示不参与判定，判定结论不再因充能改写。

**变更理由**：原口径把充能底线作为替换的硬条件，而多数角色的 `currentER` 与 `erRequirement` 同值（导入占位默认 180/180，**零余量**）——任何降低充能副词条、但词条当量明显更优的替换都会被判「不建议替换（替换后充能不足）」。实测：七七换入一件词条当量高 1.21 的羽毛（副词条充能 18.1% → 11.0%）被整体否决，与算法三「评估圣遗物本身价值」的定位不符，也让「充能」这一配置项的准确性过度支配结论。

**变更二 · 充能提示分级（Δ 口径）**

**变更内容**：充能提示由「只看替换后是否达标」（`newER < erRequirement` 即输出「充能不足」）改为**同时看「这次替换对充能做了什么（Δ = newER − currentER）」与「替换后是否达标」**，分四类（判定表见 §4.4），并以 `erTagLevel`（`lack` / `partial` / `met`）驱动 UI 配色（红 / 黄 / 绿）。

**变更理由**：原口径与「替换行为」脱钩——角色 170% / 需求 180% 时，换入一件充能更高的羽毛（newER = 175%，充能其实**提升了 5%**）仍被标成「充能不足」，与事实相反，也无法区分「帮上忙」与「帮倒忙」。

**用户确认的边界**：Δ < 0 但替换后仍达标 → 无提示（达标即不打扰）；Δ = 0 → 无提示（即便角色当前仍不足）。文案取「充能补足，还差 X%」（带缺口数值），与变更一的「缺 X%」格式一致。

**不变部分**：
- 算法二仍是「达标型」口径——**超额**部分按当量直接全扣（不区分来源），**不足**仅标签提示不扣分（见 3.4）。
- 替换后评分 `newPercent` 仍按算法二重算，如实反映充能超额惩罚；评分高低不否决判定（本就解耦）。
- 充能「未配置」（`erRequirement` / `currentER` 为 `null`，两字段在配置界面联动）→ 不做约束、也不输出提示。

**配套实现要点**：
- 判定式：`worthy = diff > MIN_DIFF`（满级）；`erConfigured` / `erOk` 仍计算并随结果返回，供 UI 展示提示与后续扩展。
- 「已配置充能」必须用 `Number.isFinite` 判定：全局 `isFinite(null) === true`（`Number(null) === 0`），会把未配置充能当成「需求 0%」，从而产生虚假的「充能不足」提示。
- **替换落库时联动面板充能**：确认替换 / 编辑已穿戴件后，由 `store.replaceArtifact` 按副词条充能贡献差写回 `currentER`（`currentER ← currentER − ERContrib(旧件) + ERContrib(新件)`，与 `evaluateAgainst` 中 `newER` 同口径）。否则面板仍显示替换前的值，首页充能徽章与详情页充能块都不会变化（与判定/评分口径自相矛盾）。仅当充能已配置（`currentER` 为数值）且差值非 0 时联动，结果保留 1 位小数。
- **主词条充能不在联动范围**：评估路径（情况一/二）本就要求主词条与被替换件一致，故替换不会改变主词条充能；若将来放开主词条替换，需一并计入主属性充能差（充能沙 51.8% 等，随等级变化）。
- **浮点尾差防护（变更二引入）**：`erDelta` 取 2 位小数、面板充能写回取 1 位小数。否则 `180 − 18.1 + 18.1 = 180.00000000000003` 会把「充能未变化」的替换判成「增加 → 充能满足」。

### 4.5 示例

> 示例 A / B / C 为**情况一（作为散件）**，示例 D 为**情况二（作为套装件）**，示例 E 为**情况一′（作为自由件，无散件场景）**。

**示例 A：情况一 · 满级散件替换**

散件部位为「杯」。当前杯加权词条数 4.85；新杯已满级（level=20），副词条为暴击率 7.8%、爆伤 15.6%、大攻击 11.6%、充能 13.0%（权值 1.0 / 1.0 / 0.8 / 0.9）。角色充能需求 180%，当前面板充能 200%，替换后 newER = 213%（充能仍满足）：

- `newCurrent = 7.8/3.9×1.0 + 15.6/7.8×1.0 + 11.6/5.8×0.8 + 13.0/6.5×0.9 = 2 + 2 + 1.6 + 1.8 = 7.4`
- `remaining = 0`，`potential = 7.4`，`diff = 7.4 − 4.85 = +2.55`
- 判定：`diff = +2.55 > 0` 且 `newER ≥ 180%` → **建议替换**，角色总分提升 2.55 个加权词条。
- 替换后评分按算法二重算（含充能惩罚：213% − 180% = 33% 超额 → 惩罚 33/6.5 ≈ 5.08 × w(充能)），评分可能低于替换前——**这是评分对充能溢出的客观反映，不否决替换结论**。

**示例 B：情况一 · 未满级散件强化决策**

散件部位为「花」。现有花加权词条数 5.60。新花 level=4（已解锁 1 次强化，剩余 4 次），副词条：暴击率 3.5%、爆伤 7.0%、大攻击 5.3%、防御力 19（无效词条，未计分）（加权 = 0.897 + 0.897 + 0.914×0.8 ≈ 2.53）。该部位可用有效词条最高权值 maxW = 1.0：

- `remaining = max(0, 5 − floor(4/4)) = 4`，无待激活词条
- `potential = 2.53 + 0 + 4 × 1.0 = 6.53`
- `diff = 6.53 − 5.60 = +0.93 ≥ 0` → **值得强化**（最完美强化后有机会超越现有花）。
- 若新花 level=4 时当前副词条很差（如 potential = 5.10 < 5.60）→ 不值得强化，直接放弃。

**示例 C：情况一 · 0 级 3 初始散件强化决策（含待激活词条）**

散件部位为「羽」。现有羽加权词条数 4.20。新羽 0 级（level=0），副词条录入：攻击力+4.1%（激活）、生命值+4.7%（激活）、充能+6.5%（激活）、**防御力+19（待激活）**。该角色有效词条：暴击率(1.0)、爆伤(1.0)、攻击力百分比(0.8)，防御力非有效词条；maxW = 1.0：

- `newCurrent = 攻击力4.1%→0.707×0.8 + 生命值非有效→0 + 充能6.5%→1.0×w(充能)`
  - 若充能权值 0.6，则 `newCurrent = 0.566 + 0 + 0.6 = 1.166`
- `pending = [防御力+19]`，`pendingContrib = (19/23) × w(防御力) = 0.826 × 0 = 0`（防御力非有效词条）
- `remaining = max(0, 5 − floor(0/4)) = 5`
- `potential = 1.166 + 0 + (5 − 1) × 1.0 = 5.166`
- `diff = 5.166 − 4.20 = +0.966 ≥ 0` → **值得强化**（解锁防御力虽无贡献，但剩余 4 次叠加全部理想时有机会超越现有羽）。

**示例 D：情况二 · 套装件替换（同部位同套装同主词条）**

角色配装：4 件「绝缘之旗印」（花/羽/沙/头）+ 散件杯（looseSlot = 杯）。新沙 level=20（满级），套装 = 绝缘之旗印，主词条 = 攻击力百分比，副词条加权 6.20；当前已穿戴沙同为绝缘之旗印、攻击力百分比，加权 5.10：

- 情况二适用：`newArtifact.set == equipped.set` 且 `mainStat` 相同 → 与当前沙比较
- `diff = 6.20 − 5.10 = +1.10 > 0` → **建议替换**（判定只看词条提升；替换后充能是否达标不再影响判定，若不足则额外附「充能不足，缺 X%」提示），绝缘套件数不变（仍是 4 件），套装效果不受影响
- 情况一不适用：新沙部位（沙）≠ looseSlot（杯）→ 无散件场景
- 汇总：情况二值得 → **有价值**

> 若新沙的套装不是绝缘之旗印（如「深林的记忆」），则情况二不适用（套装不同）；若该部位也不在自由位内，则无任何适用情况 → 无适用场景。

**示例 E：情况一′ · 自由件替换（无散件 · 5 件全套装）**

角色配装：5 件「炽烈的炎之魔女」（花/羽/沙/杯/头），`looseSlot` 为空（无散件）。有效词条 暴击率 1.0 / 暴击伤害 1.0 / 攻击力百分比 0.8 / 元素充能效率 0.6，充能需求与面板充能同为 180%；5 件现有件副词条均为 暴击率 3.9% / 爆伤 7.8% / 大攻击 5.8% / 充能 6.5%（单件 3.40 当量，角色总分 17.00，`perfectTotal = 40.2`）。新件 = 异套（角斗士的终幕礼）火伤杯，满级，副词条 暴击率 10.5% / 爆伤 21.0% / 大攻击 13.5% / 充能 16.5%：

- **自由位判定**：`looseSlot` 为空，除杯外其余 4 件同属魔女套 → 杯是自由位；5 件全同套时 5 个部位**全部**为自由位（任意一件都是冗余件，换掉后仍是 4 件套）
- 主词条一致（火伤杯 → 火伤杯）→ 情况一′适用，比较对象 = 当前杯
- `newCurrent = 10.5/3.9 + 21.0/7.8 + 13.5/5.8×0.8 + 16.5/6.5×0.6 = 2.692 + 2.692 + 1.862 + 1.523 = 8.77`
- `diff = 8.77 − 3.40 = +5.37 > 0`；`newER = 180 − 6.5 + 16.5 = 190 ≥ 180` → **建议替换**
- 替换后评分：`newTotal = 17.00 − 3.40 + 8.77 = 22.37`，充能惩罚 `(190 − 180)/6.5 × 0.6 = 0.92` → `21.45 / 40.2 = 53.3 分`
- 情况二不适用（套装不同）；`isSetSwap = false`——**无散件可失去**（该部位本就是冗余件，替换后仍是 4 件魔女套，套装效果不变）
- 汇总：情况一′值得 → **有价值**

> 对照：同一角色若为 4 件魔女 + 1 件异套（`looseSlot` 仍为空），则只有那 1 件异套部位是自由位；异套件换到 4 件套的任一部位会破坏 4 件套 → 不评估（对应该部位「无适用场景」）。

## 五、算法四：圣遗物重塑价值评估

### 5.1 目标与适用范围

判断哪些满级 5★ 圣遗物更值得消耗「启圣之尘」进行重塑，覆盖两类对象：

- **角色已有圣遗物**（存量）：当前强化分配已定，按 5.5 三情况归属规则确定评估对象（自己 / 同套宿主），判断「重掷全部强化（或重塑后转移）能否期望变好」；
- **新输入圣遗物**（满级件）：视为无持有者的游离件，按情况三口径评估「装备其所属套装」的角色；**未满级件不进重塑排序**，仅按算法三输出培养潜力（可附注重塑期望终态，见 5.9）。

重塑机制要点（5.7 版本实装的游戏规则）：

| 规则 | 内容 |
|------|------|
| 适用对象 | 仅 5★ 满级（level=20）圣遗物 |
| 重塑内容 | 4 条副词条**种类不变**，仅重新分配全部强化落点；初始词条数值不变 |
| 词条指定 | 重塑前指定 2 条期望词条，保底合计命中：基础档 ≥2 次 / 高阶档 ≥3 次 / 谕告档 ≥4 次 |
| 圣言解明 | 账号级共享进度：每 1 枚尘 +1 点，满 6 点触发高阶档；每 2 次高阶后下一次为谕告档 |
| 尘消耗 | 花/羽 1 枚、沙/杯/头 2 枚（进度按尘数积累 → 各部位终保底所需总尘相同） |
| 结果选择 | 重塑后可预览并选择「维持原状」或「采用结果」，尘不返还 |

### 5.2 机制建模：安全网分布

游戏实现为「逐次独立随机强化，当剩余次数恰好等于保底缺口时，剩余强化强制命中指定词条」（动态检测）。该机制与**安全网分布**（下缩并，Lower-Winsorized）数学等价：

```
X ~ B(n, 1/2)      # 自由随机下的命中次数：每次强化等概率命中 4 词条之一，指定 2 词条合计 p = 1/2
Y = max(X, k)      # 安全网：低于 k 的结果全部托至 k，高于 k 的保持原样
```

- `n`：可重掷的强化次数。**4 初始 = 5；3 初始 = 4**（1 次强化被第 4 词条解锁占用，该词条及其数值在重塑中不变）。
- `k`：保底阈值。基础 2 / 高阶 3 / 谕告 4。

安全网期望命中次数：

```
E[Y_k] = n/2 + Σ_{x=0}^{k−1} C(n,x)/2ⁿ · (k−x)
```

| n \ k | 基础 k=2 | 高阶 k=3 | 谕告 k=4 |
|-------|---------|---------|---------|
| 5（4 初始） | 2.71875 | 3.21875 | 4.03125 |
| 4（3 初始） | 2.375 | 3.0625 | 4 |

> 模型出处：NGA《[数据讨论] 托底不抬天花板：圣遗物重塑的安全网模型与期望计算》（tid=47452649）及其前作《[抛砖引玉] 圣遗物高级重塑的定量分析和胚子选择策略》（tid=45982193，DP 递推版）。两文论证了动态检测与安全网的等价性；本节通用式已在其口径下交叉验证（见 5.7 注）。

### 5.3 重塑期望与价值分（RV）

记该件 4 条副词条对角色 R 的权值为 `w1 ≥ w2 ≥ w3 ≥ w4`（无效词条 w = 0）。**w1、w2 为建议指定的 2 条期望词条**：因保底使 E[Y_k] ≥ n/2，E[remodel] 随 (w1+w2) 单调递增，故指定权值 top2 严格最优。w3、w4 为其余两条。`Σw_init = w1+w2+w3+w4` 为全部副词条的有效权值和。

每次强化的数值档位 70% / 80% / 90% / 100% 四档等概率 → 档位期望 `ROLL_AVG = 0.85`，且与落点独立。

**重塑后总当量期望**——初始 4 条词条在重塑中不变（每条按 1 次档位期望 0.85 当量计入），n 次强化按安全网期望分配：

```
E[remodel] = ROLL_AVG × [ Σw_init + E[Y_k]·(w1+w2)/2 + (n−E[Y_k])·(w3+w4)/2 ]
```

- 命中指定词条共 Y 次，每次期望贡献 `(w1+w2)/2` 当量；非命中 `n−Y` 次落另外两词条，每次期望贡献 `(w3+w4)/2`；
- 无保底退化（E[Y] = n/2）时 `E[remodel] = ROLL_AVG × (1 + n/4) × Σw_init`，n=5 时即 1.9125 × Σw_init。

**价值分与判定**：

```
RV = E[remodel] − baseline              # 统一骨架：重塑后期望分 − 功能位现状分
期望达成度 = E[remodel] / perfect(slot)   # perfect 复用算法二（主词条占用已计入）
```

`baseline`（功能位现状分）按 5.5 三情况归属规则取值：

| 情况 | 行动语义 | baseline 取法 |
|------|---------|--------------|
| 一（套装件 → 自己） | 原地强化 | X 对持有者的当前评分（功能位现状 = X 自己） |
| 二 / 三（转移宿主） | 顶替转移 | 宿主现有同部位同主属性件的评分（功能位现状 = 被顶替者） |

**判定**：RV > 0 → 值得重塑（进入候选，按 RV 降序参与排序）；RV ≤ 0 → 不值得（当前功能位现状已达/超过重塑期望，期望负收益）。

- **RV 语义**：净期望提升。情况一衡量「原地重掷」的净收益；情况二/三衡量「重塑 + 转移」组合行动对宿主的净提升（与算法三替换比较同口径——不减宿主现状会高估收益）。组合 Σw_init 高且当前分配歪 → RV 大；现状已接近组合期望（如接近毕业的极品件）→ RV 趋零或为负，模型自动避免推荐重塑毕业件。
- **组合天花板**（展示用，满挡口径）：`ceiling = Σw_init + n × maxW'`（maxW' 为该件有效词条最高权值，每次强化按满挡 1 当量计）。重塑无法突破组合上限——「托底不抬天花板」。

### 5.4 保底线（三档确定性下限）

指定 top2 后，按最坏分配估计的得分下限（保底命中在 w1/w2 间按最少收益拆分，其余强化全歪、贡献 0）：

| 档位 | 保底命中 | 下限公式 |
|------|---------|---------|
| 基础档 k=2 | 2 次 | `ROLL_AVG × [Σw_init + (w1 + w2)]` |
| 高阶档 k=3 | 3 次 | `ROLL_AVG × [Σw_init + (w1 + 2·w2)]` |
| 谕告档 k=4 | 4 次 | `ROLL_AVG × [Σw_init + 2·(w1 + w2)]` |

用途：辅助决策「现在洗（基础档）还是攒圣言解明进度到高阶/谕告再洗」。谕告档下限已接近组合天花板（n=4 时无剩余自由强化，n=5 时仅剩 1 次）。

### 5.5 评估流程（三情况归属规则）

1. **硬过滤**：5★ 且 level=20；至少 1 条有效词条（w1 > 0）。
2. **归属判定（三情况）**：对每件候选 X（持有者 A；会话内新录入件视为**无持有者的游离件**），确定可评估对象集合：

   | 情况 | X 对持有者 | 判定条件 | 评估对象 |
   |------|-----------|---------|---------|
   | 一 | 套装件（slot ≠ A.looseSlot） | 恒成立 | A 自身 |
   | 二 | 套装件 | 存在 Y ≠ A：Y 装备 X 所属套装 且 Y 有同部位同主属性件 | 满足条件的每个 Y |
   | 三 | 散件（slot == A.looseSlot） | 同情况二条件 | 满足条件的每个 Y（**不含 A 自身**） |

   - **「Y 装备 X 所属套装」**：Y 的非散件部位中存在 set == X.set 的已穿戴件。此时 X 对 Y 是天然的套装件。
   - **「同部位同主属性件」**：Y 在 X 同部位装备的圣遗物主词条与 X 相同；该件对 Y 的套装归属**不限**（是散件亦纳入——同样获得凑件数收益）。主词条约束源于「重塑不改主词条」：X 重塑后仍是原主词条，无法替代主属性不同的功能位；若 Y 需要该主属性，用散件即可满足，无需重塑。
   - **散件不评自身**：散件可随时被新获取的散件替换，不值得消耗重塑道具；散件唯一有价值的重塑场景是其恰好为其他角色的套装件（情况三）。
   - **收益结构**：情况三转移后 X 晋升为 Y 的套装件（Y 凑成更高件数套装，可把相对最差的部位退为散件再优化），A 仅损失一个散件位、补任意散件即可——整体正收益；情况二转移会打破 A 的套装构成（双侧有代价，仍纳入评估供玩家权衡）。
3. **逐对象计算**：对每个可评估对象 t，按其权值计算 E[remodel]、期望达成度、三档保底线，并按 5.3 表取 baseline：情况一 `baseline = score(X, A)`；情况二/三 `baseline = score(宿主现有件, Y)`。`RV = E[remodel] − baseline`。
4. **互斥取最优**：同一件 X 的多个可评估行动互斥（重塑后的件只能装备在一处），每件取 **RV 最大的行动**作为唯一记录展开（展开项含全部可评估对象）；RV 并列时按行动列表顺序取先（自己优先于宿主，实现为稳定排序）；无可评估对象的件（如散件无宿主、持有者外无有效配置、行动全被三情况开关关闭）不进入列表。
5. **排序输出**：主排序按**基础档 k=2** 的 RV 降序（保守口径，不依赖账号圣言解明进度状态）；UI 支持切换按高阶 k=3 / 谕告 k=4 排序。
6. **n 判定（3/4 初始）**：新输入件由录入面板选择（游戏重塑界面直接标注 3/4 初始）；存量满级件由**单发档位分解自动推断**（`inferInitialCount`，见 5.6）：按「4 初始 = 4 发初始 + 5 次强化 = 9 发；3 初始 = 3 发初始 + 1 发解锁第 4 条 + 4 次强化 = 8 发」的守恒关系，对每条副词条枚举可行发数 k∈1..5（显示值必为 k 个单发档位值之和），四条可行 k 的总和**仅可能等于 9 → 判 4 初始**、**仅可能等于 8 → 判 3 初始**；两可或无法分解（异常值/待激活条目）→ 回退默认 4 初始。UI 二态：**推断明确（唯一判定）→ 静态展示不可切换**（确定值防止误切）；**两可/无判据 → 提供单件切换按钮**（会话内记忆覆盖值，仅对无判据件生效）。**不新增持久化字段**。
7. **三情况开关（UI 会话内过滤）**：三种行动类别——**原地强化**（self，情况一）/ **同套转移**（transfer，情况二）/ **晋升套装件**（promote，情况三）——支持任意组合开启或关闭（会话内状态，不持久化）。关闭的类别**不参与评估**：行动先按 kind 过滤，每件再在剩余行动范围内取 RV 最优；全部关闭时无行动可评估，列表为空并给出提示。开关只改变「取最优的行动范围」，**不改变单条行动的 RV 计算**（各行动的 RV 口径与全开时完全一致，故跨开关状态的结论可复算）。

### 5.6 伪代码

```
const ROLL_AVG = 0.85                       # 档位期望（70/80/90/100% 等概率）
const K_LEVELS = { basic: 2, advanced: 3, oracle: 4 }
const DUST_COST = { flower: 1, plume: 1, sands: 2, goblet: 2, circlet: 2 }

function expectedHits(n, k):                # 安全网期望 E[Y_k]
    e = n / 2
    for x in 0 .. k-1:
        e += comb(n, x) / 2^n * (k - x)
    return e

function calcRemodel(artifact, role, k = 2, initialCount = 4):
    if artifact.level < 20: return null     # 仅满级件
    ws = artifact.substats
        .map(s => s.stat in role.effectiveStats ? role.weights[s.stat] : 0)
        .sort(desc)                          # 无效词条权值 0
    w1 = ws[0] ?? 0; w2 = ws[1] ?? 0; w34 = (ws[2] ?? 0) + (ws[3] ?? 0)
    if w1 <= 0: return null                  # 无有效词条，重塑无意义
    sumW = w1 + w2 + w34                     # Σw_init
    n = initialCount == 3 ? 4 : 5           # 3/4 初始 → 重掷 4/5 次（判定见 inferInitialCount / 5.5 第 6 条）
    eY = expectedHits(n, k)
    eRemodel = ROLL_AVG * (sumW + eY*(w1+w2)/2 + (n-eY)*w34/2)
    cur = calcArtifactScore(artifact, role)  # 算法一
    return {
        w1, w2, w34, n, k, eY,
        eRemodel, currentScore: cur,
        rv: eRemodel - cur,                  # 主排序指标
        achieve: eRemodel / calcPerfect(artifact.slot, role),   # 期望达成度（算法二）
        floors: {                            # 三档保底线
            basic:    ROLL_AVG * (sumW + (w1 + w2)),
            advanced: ROLL_AVG * (sumW + (w1 + 2*w2)),
            oracle:   ROLL_AVG * (sumW + 2*(w1 + w2)),
        },
        ceiling: sumW + n * w1,              # 组合天花板（满挡口径）
        dust: DUST_COST[artifact.slot],
        efficiency: (eRemodel - cur) / DUST_COST[artifact.slot],   # 单位材料效率
    }

function wearsSet(role, setName):           # 「Y 装备套装 S」判定（5.5 情况二/三宿主条件）
    for slot in SLOTS:
        if slot == role.looseSlot: continue  # 散件位不算装备套装
        a = role.artifacts[slot]
        if a and a.set == setName: return true
    return false

function inferInitialCount(artifact):       # 3/4 初始自动推断（5.5 第 6 条）：档位分解判总发数
    if artifact.level < 20 or 激活副词条数 != 4: return null   # 满级恒 4 条；不足则无判据
    R = for each 激活副词条 s:               # 显示值 = k 个单发档位值（ROLL_TIERS 四档）之和
        ks = { k in 1..5 : s.value 可分解为 k 个档位值之和 }
        if ks 为空: return null              # 数值无法由档位分解（超限录入等）
    can4 = 存在 k1..k4 分属 R[0..3] 使 k1+k2+k3+k4 == 9
    can3 = 同上，总和 == 8
    if can4 and not can3: return 4          # 4 初始 = 4 发初始 + 5 次强化 = 9 发
    if can3 and not can4: return 3          # 3 初始 = 3 发初始 + 1 发解锁 + 4 次强化 = 8 发
    return null                             # 两可或皆否 → 调用方回退默认 4 初始

function remodelTargets(X, sourceRole, roles):   # 三情况归属判定 → 可评估对象集合（含 kind 类别标记）
    targets = []
    sameFunc = r => r != sourceRole
                    and wearsSet(r, X.set)
                    and r.artifacts[X.slot] and r.artifacts[X.slot].mainStat == X.mainStat
    hostKind = (sourceRole and X.slot != sourceRole.looseSlot) ? "transfer" : "promote"
               # X 对持有者是套装件 → 宿主行动 = 同套转移；X 是散件/游离件 → 宿主行动 = 晋升套装件
    if sourceRole == null:                   # 新录入件（游离件）：按情况三口径
        targets += [ {role: r, case: "host", kind: "promote"} for r in roles if sameFunc(r) ]
    else if X.slot != sourceRole.looseSlot:  # 套装件：情况一 + 情况二
        targets += [ {role: sourceRole, case: "self", kind: "self"} ]
        targets += [ {role: r, case: "host", kind: hostKind} for r in roles if sameFunc(r) ]
    else:                                    # 散件：仅情况三（不评自身）
        targets += [ {role: r, case: "host", kind: hostKind} for r in roles if sameFunc(r) ]
    return targets

function analyzeRemodel(candidates, roles, k = 2, initialCountOf, allowedKinds = null):
    # initialCountOf：candidate => 3|4（5.5 第 6 条 n 判定；UI 链：inferInitialCount 档位推断〔明确时忽略覆盖〕> 手动切换〔仅两可/无判据件〕> 默认 4）
    # allowedKinds：开启的行动类别子集（["self","transfer","promote"]）；缺省 = 全部开启（三情况开关）
    allowed = allowedKinds == null ? null : set(allowedKinds)
    results = []
    for X in candidates where X.level == 20 and 为 5★:
        per = []
        for t in remodelTargets(X, X.sourceRole, roles):
            if allowed and t.kind not in allowed: continue   # 关闭的类别不参与评估
            r = calcRemodel(X, t.role, k, initialCountOf(X))
            if r == null: continue           # 该对象下无有效词条 → 跳过
            baseline = (t.case == "self") ? r.currentScore
                                          : calcArtifactScore(t.role.artifacts[X.slot], t.role)
            rv = r.eRemodel - baseline       # 统一骨架：重塑后期望 − 功能位现状
            per.append({ role: t.role, case: t.case, kind: t.kind, baseline, rv, ...r })
        if per.length == 0: continue         # 无可评估对象（散件无宿主、行动全被关闭等）→ 不进列表
        best = max(per, by = rv)             # 互斥行动在开启范围内取最优（每件一条记录）
        results.append({ artifact: X, best: best, all: per })
    sort(results, desc by best.rv)           # 基础档 k=2 主排序
    return results
```

### 5.7 示例

角色有效词条：暴击率(1.0)、爆伤(1.0)、大攻击(0.8)、精通(0.6)（同算法一示例角色）。两件满级 **4 初始**花（主词条生命值，不占用有效词条），**词条组合相同**（暴击/爆伤/大攻击/精通，4 条全有效），仅强化分配不同：

| 件 | currentScore（算法一） | 构成 | 状态 |
|----|------|------|------|
| 甲 | 6.31 | 暴击 1.90 + 爆伤 1.87 + 大攻 1.45 + 精通 1.10（同算法一示例） | 分配好，接近组合期望 |
| 乙 | 4.30 | 暴击 1.90 + 爆伤 1.00 + 大攻 0.80 + 精通 0.60 | 3 次强化歪向低当量落点 |

组合参数：`w1=1.0（暴击）、w2=1.0（爆伤）、w3+w4=1.4（0.8+0.6）、Σw_init=3.4、n=5`。

**E[remodel]（基础档 k=2，E[Y₂]=2.71875）**：

- 强化期望词条数 = 2.71875×(2.0/2) + (5−2.71875)×(1.4/2) = 2.71875 + 1.596875 ≈ 4.316
- `E[remodel] = 0.85 × (3.4 + 4.316) ≈ 6.56`

| 件 | RV = 6.56 − currentScore | 期望达成度 | 结论 |
|----|------|------|------|
| 甲 | **+0.25** | 6.56 / 8.4 ≈ 78% | 期望增益微小，不急于重塑 |
| 乙 | **+2.26** | ≈ 78% | **优先重塑**（同组合下收益远高于甲） |

保底线（乙）：基础 **4.59** / 高阶 **5.44** / 谕告 **6.29**；组合天花板 ceiling = 3.4 + 5×1.0 = **8.4**（恰等于该角色 perfect(花)，因该件 4 词条即角色的全部有效词条）。

> 同组合、不同分配，RV 相差近一个数量级——「值得重塑」的本质是**组合好 + 分配歪**，与「托底不抬天花板」一致：甲的 current 已接近组合期望，重塑期望增益趋零。
>
> 口径交叉验证：本节通用式在纯词条计数口径（无 0.85、无 Σw_init）下可复现 NGA 原文数值——情形一 3.21875（n=5,k=3）、情形二 3.53125（n=4,k=3，第三词条权重 1）、玛薇卡例 4.2875（n=5,k=3，权重 1/1/0.6/0.6）。

### 5.8 附加展示维度（不进主公式）

| 维度 | 定义 | 用途 |
|------|------|------|
| 单位材料效率 | `efficiency = RV / DUST_COST` | 同收益下花羽（1 尘）效率为沙杯头（2 尘）的两倍 |
| 被替代风险 | 定性标记 | 花/羽出货快，重塑收益易被新胚子覆盖；沙/杯/头主词条稀缺，重塑结果更保值 |
| 建议指定词条 | 权值 top2 有效词条（w1、w2） | UI 直接给出重塑时应选的 2 条词条 |
| 圣言解明进度 | 账号状态（不建模） | 三档保底线辅助决定「现在洗还是攒谕告档」 |

### 5.9 与算法三的关系及本算法边界

- **与算法三的衔接**：算法三 potential 在满级时退化为 currentScore（强化路径关闭）；算法四把满级件的提升路径从「继续强化」换成「重掷全部强化」，情况一下 `RV = E[remodel] − currentScore` 是 potential 思想在重塑场景的推广——ceiling（组合天花板）对应 potential 的乐观上限，E[remodel] 是它的期望版；情况二/三的「减宿主现有件分」则与算法三的替换比较同口径。
- **三情况偏差方向（已知、单向）**：情况一 RV 精确（无未计入项）；情况三**低估**——宿主凑成更高件数套装后可把相对最差部位退为散件再优化，这笔套装凑整收益未计入，实际收益略高于显示值；情况二**高估**——持有者套装被打破、需重构的代价未计入，实际收益略低于显示值。偏差方向固定，在 UI 文案中提示，不影响排序可用性。
- **未满级新输入件**：不进重塑排序，按算法三输出培养潜力；可附注「若满级后分配不佳，重塑期望终态 = E[remodel]」（同一公式）。
- **初始档位近似**：Σw_init 按「每条初始词条 = 1 次强化档位期望（0.85 当量）」计入，与实际初始档位（0.7~1.0）存在每条 ±0.15 的无偏波动；如需精确，可录入每条词条的强化次数（游戏详情页可见）反推初始值，一期不做。
- **充能词条**：按权值表线性参与全部计算。两点需人工复核：① 已达标角色（currentER ≥ erRequirement），命中充能实际为浪费，计算值偏高，建议改选其他有效词条；② 严重缺充能角色，命中充能有「补达标」的阶跃价值，线性期望未刻画，结合算法二充能不足标签判断。
- **RV 是期望不是保证**：实际重塑结果可预览、可放弃（维持原状），RV > 0 仅表示「值得花尘尝试」；谕告档下的确定性收益以 5.4 保底线为准。

## 七、设计说明与边界

1. **滚数当量口径**：以「满挡单发（Umax）」为单位，天然支持跨词条比较（暴击 1 当量 = 精通 1 当量 = 大攻击 1 当量），权值再体现角色偏好。
2. **加权 vs 原始**：`rolls × w(stat)` 兼顾「词条质量」与「角色适配度」；若所有有效词条权值均为 1，退化为普通有效词条计数。
3. **百分比词条单位**：value 与 Umax 必须同单位（百分数），避免当量失真。
4. **完美态上限**：`init` 计前 4 条权值最高的有效词条（副词条上限 4 条）；`5×maxW` 按最优分配，保证分母为真实理论上限，评分天然 ≤ 100。
5. **主词条占用**：依据不重复原则，主词条若为有效词条，则从该部位可用有效词条中扣除（见 3.2）。
6. **充能阈值**：充能为「达标型」属性——超额部分按当量**直接全扣**（不区分来源），不足部分仅标签提示不扣分（见 3.4）。替换时通过充能贡献差联动重算面板充能与评分：评估阶段由算法三 `evaluateAgainst` 计算 `newER` 与替换后评分；确认替换/编辑已穿戴件后由 `store.replaceArtifact` 按同一差值写回角色的 `currentER`（见 §4.4 口径变更记录）。评分封底 0 分，避免充能惩罚过大时出现负分。
7. **潜力评估统一**：散件评估覆盖「满级替换」与「未满级强化决策」两种场景，通过 `remaining = max(0, 5 − floor(level/4))` 统一；满级时 remaining=0 自动退化为替换评估。
8. **强化潜力口径**：叠加强化按「最完美」计（满挡 1 当量 + 砸中权值最高有效词条），是乐观上限；实际强化结果低于潜力值，判定「值得强化」仅表示有超越机会。
9. **判定与评分解耦**：算法三的「判定」与「替换后评分」是两件事——判定**只看词条提升**（充能不足只提示、不否决，见 §4.4 口径变更记录）；评分看替换后角色整体水平（算法二口径，含充能超额惩罚与不足标签）。两者独立：即使替换后评分因充能溢出下降，只要词条有提升，判定仍为「建议替换」，评分仅供展示参考。充能提示按「Δ 与替换后是否达标」分四类（不足红 / 补足黄 / 满足绿，见 §4.4），是否替换由使用者结合实战判断（例如队伍有其他充能来源时不构成问题）。
10. **3 初始 / 待激活词条**：待激活词条的**属性和数值均由用户录入确定**（如防御力+19），4 级解锁后直接生效，按录入数值计算当量计入潜力（`pendingContrib`，与算法一同口径）；解锁占用 1 次强化，故 3 初始潜力上限天然低于 4 初始（少 1 次叠加），与游戏实际一致。
11. **评估范围（三种适用情形）**：算法三评估新圣遗物的一切潜在使用方式——情况一（作为散件替换 looseSlot）、情况一′（作为自由件：`looseSlot` 为空时按套装结构自动识别冗余位，5 件全同套则 5 个部位均为自由位）与情况二（作为套装件，同部位同套装同主词条替换）。三者替换前后套装构成均不变，同样满足忽略套装效果的评估前提，判定口径一致；汇总时任一情况值得即有价值。若未来需要 2+2+1 等分散套装的全量重算（如允许跨套装重组），需补充套装加成数值模型。
12. **主词条**：当前默认全对，评估算法提供可选校验入口（validMainStats），未配置时跳过。
13. **重塑建模口径**：安全网分布 Y = max(X, k)（出处 NGA tid=47452649 / tid=45982193），与游戏「动态检测」实现数学等价；RV 为期望净收益而非保证收益——重塑结果可预览、可放弃，RV > 0 仅表示值得花尘尝试。
14. **档位期望近似**：ROLL_AVG = 0.85 为四档等概率期望；初始词条按 0.85 当量计入（无偏近似，每条 ±0.15 波动），对排序影响有限；如需精确可录入词条强化次数反推初始值（见 5.9）。
15. **托底不抬天花板**：重塑不改变词条组合，ceiling 由组合唯一决定；currentScore 接近 ceiling 的毕业件 RV 自然趋零，模型自动避免误导性推荐。
16. **算法四零数据模型改动**：不新增持久化字段；3/4 初始（n 判定）由档位分解自动推断（5.5 第 6 条）——推断明确静态展示不可切换，两可/无判据件提供切换按钮（会话内覆盖，不持久化）；新输入件由录入面板选择。
17. **三情况归属规则**：重塑分析的评估对象由归属规则确定（见 5.5）——套装件评自己（原地强化）与「装备同套装且有同部位同主属性件」的宿主（顶替转移），散件仅评「装备其所属套装」的宿主（晋升套装件、不评自身），新录入件按游离件走情况三口径；RV 统一为「重塑后期望分 − 功能位现状分」（情况一减自己、二/三减宿主现有件）；同一件的多个可评估行动互斥，每件取 RV 最优行动输出一条记录。
