## 一、总体结论

**骨架良好，不需要推翻重来。** 当前处于「细节已精雕、系统层欠账」的状态：

- **已成熟**：Apple 材质分层（深+金 / 浅+蓝双主题）、完整 token 体系、反馈层（弹窗焦点管理/Toast/滚动锁）、深色主题对比度（全部达标 ≥5.2:1）、数据表格化布局（藏品页/评估行）、减弱动效支持
- **待偿还（按严重度）**：
  1. 浅色主题语义色**系统性不达标**（实测 1.5~3.6:1，见 2.1）
  2. 数据正文字号**跌破 12px**（藏品页 74% 正文为 11px，见 2.2）
  3. 全站图标为 **emoji/字符**（跨平台渲染不一致，见 2.3）
  4. **移动端首页角色卡布局崩坏**（见 2.4）
  5. 布局与语义遗留：详情页 4+1 孤行、红色双重语义、残留间距等（见 2.4/2.6）
- **建议路线**：保留骨架，四层递进 —— **缺陷修复 → 设计基座 → 图标系统 → 信息架构与交互**。全程不改变类名与数据结构，算法/数据层零改动，测试可作回归闸门。

> 说明：如果你想要的是「完全换一套视觉」的重设计（例如更原神化的皮肤），那是另一条路线、需要单独定方向；本方案走的是「把现有设计做扎实」的路线。

## 二、审计发现明细

### 2.0 审计方法（可复核）

- 实拍截图 29 张 + 度量数据存于 `.workbuddy/audit/`（工作数据，不入库）：`metrics.json`（字号直方图/控件尺寸/溢出）、`metrics2.json`（双主题对比度采样）
- 对比度 = 计算样式颜色按实际叠加合成后，与有效背景的 WCAG 对比度（黑盒采样，非目测）
- 下文所有数字均为实测值

### 2.1 无障碍与对比度

**浅色主题语义色不达标（重灾区）** —— 要求：正文 4.5:1，大字号（≥24px 或 ≥18.7px 粗体）3:1：

| 元素 | 实测 | 判定 |
|---|---|---|
| 「满级可期」徽章（黄 #ffcc00） | 1.51 | ✗ 严重 |
| 评估汇总条「✓ …有提升」（绿） | 1.99 | ✗ 严重 |
| 藏品「满级最值 / 最值%」（绿） | 1.77 | ✗ 严重 |
| 充能徽章（绿 #34c759） | 2.22 | ✗ |
| 词条差「+1.01 词条」（绿） | 2.22 | ✗ |
| 藏品新件值（红 #ff3b30） | 2.83 | ✗ |
| 「充能不足」徽章（红） | 3.55 | ✗ |
| 部位达成度百分比（红，15px 粗体） | 3.55 | ✗ |
| 「无充」徽章（灰） | 3.26 | ✗ |
| 藏品套装名（11px 灰） | 4.20 | ✗（贴线差值） |
| 主按钮「＋ 新建角色」（白字 / #007aff 底） | 4.02 | ✗（差 0.5） |
| 大分数 78.4（蓝，22px 粗体） | 4.02 | ✓ 边缘（大字阈值 3.0） |

**对照：深色主题全部达标**（最低 4.68，绝大多数 ≥5.2），唯一贴线项为藏品套装名 4.68。→ **修复聚焦浅色主题；深色仅一处微调。**

原因分析：浅色主题的语义色沿用了 Apple 系统色原值（#34c759 / #ffcc00 / #ff3b30），这些颜色设计给「图形/填充」用，直接当**小号文字色**放在白底上必然不达标。此前已为「止损容错」列单独定制过深金 `#755d00`（既有成例），本方案把这套做法推广为系统性的 **ink 变体**（文字色加深、底色调保持不变）。

### 2.2 排版（字号）

实测字号直方图（文本元素）：

| 页面 | 分布 | 问题 |
|---|---|---|
| 首页 | 11px×77 · **11.5px×385** · 12px×549 · 13px×63 · 16px×79 · 22px×77 | <12px 共 462 处（37%） |
| 藏品页 | **11px×670（74%）** · 14px×102 · 15px×121 | 正文几乎全部 11px |
| 详情页 | 11px×21（rolls）· 12px×20 · 13px×40 · 15px×18 | rolls 11px |

- 11.5px 的**部位徽章**（首页核心数据）、11px 的**藏品全套数据行**（套装/等级/副词条/百分比）、11px 的 rolls，都低于数据密集类界面 12–14px 的通行下限；中文笔画密度高，11px 中文可读性尤其差
- 其余字号梯度（12/13/14/15/17/22/26/48）与字重层级、tabular-nums 均合理，无需变动

### 2.3 图标（emoji / 字符）

全站用字体字符充当图标，共 14 种以上：`⚖ ♻ 🏆 ⇪ ⇩ ☾ ☀`（顶栏）、`← ⚙ ✎ 🗑`（详情操作）、`✕ ⚠ ⓘ ✓ ✗ ＋`（状态/操作）、空态 `🏺 ⚖️ ♻️ 🔍 ✨`。

问题：
1. **跨平台渲染不一致**：🏆 等在现代浏览器渲染为彩色 emoji，与 ＋/⇪ 等单色符号混排（Windows 实拍可见彩色奖杯与黑色天平并存），Mac/Linux 渲染又不同；视觉语言不统一、不可 token 化（颜色/粗细不受控）
2. 与 Apple 风格（克制的线性图形语言）冲突，是「不够精致」观感的主要来源之一
3. 技能规范库明确列为反模式（No emoji as icons），且《UI优化说明》「后续可优化项」中早已列出「部位图标（内联 SVG）」——方向有共识

### 2.4 布局

| # | 发现 | 说明 |
|---|---|---|
| 1 | **【缺陷】移动端首页角色卡崩坏** | 390px 下：部位徽章逐行竖排、不同卡换行方式还不一致、状态徽章错位悬空（实拍可见）。≤900px 的降级规则不足以支撑该行结构 |
| 2 | 详情页 5 部位卡 **4+1 孤行** | 容器 1200px（内容 1160px），`minmax(225px)` 最多 4 列 → 第 5 张（理之冠）永远落单，右侧留大片空白。桌面端恒定如此 |
| 3 | 藏品页 <1000px 横向滚动 | `min-width:700px` 固定，窄屏靠横向滚动，移动端体验差 |
| 4 | 残留间距 | `.rc-line` 的 `padding-right:30px` 是「首页删除按钮」时代的遗留（按钮已撤），造成行内容右缩进不对称（左 16 / 右 46） |
| 5 | 材质语言混用 | `.coll-bucket` 带 1px 描边，其余所有卡片均为「无边框材质分层」——全站唯一例外 |

### 2.5 交互与 UX

| # | 发现 | 说明 |
|---|---|---|
| 1 | 首页无搜索 | 77 个角色仅能按套装/散件筛，无法按名字找。角色规模已远超「肉眼扫列表」的舒适区 |
| 2 | 首页角色卡键盘不可达 | `.role-card` 是 `div` 无 `tabindex`，Tab 键跳不进去（详情页按钮组可键盘操作，标准不一致） |
| 3 | 藏品部位跳转按钮过小 | 23px 高 / 11px 字，低于 WCAG 2.2 的 24px 最小指针目标建议；移动端更小 |
| 4 | 顶栏 7 个动作平铺 | 「导入/导出」为低频操作却与核心入口同权重并排；窄屏需折两行 |
| 5 | 空卡可点、有卡不可点 | 详情页：空部位卡点击直接录入，已有卡点击无响应（编辑只能走右上角「编辑」二级弹窗）。**这是既有决策**（§3.2「无编辑按钮」），列入待议而非缺陷 —— **已决（批次 5）：点已有卡 = 直接打开该部位编辑弹窗**（与空卡对称） |

### 2.6 色彩语义

**红色一色四义**，同页并存时易误读：

| 红色出现处 | 含义 |
|---|---|
| 部位达成度边框 / 百分比（>80%，如 91.2% 红） | **正面**·顶级 |
| 「充能不足」徽章 | 负面·警示 |
| 「删除」按钮 / diff 负值（-x.xx 词条） | 危险 / 负向 |

绿色同理有「有效词条（好）」与「达成度 <50%（差）」的双义（绿=最差档）。属既有配色规范（红橙紫蓝绿五档分级），但系统内语义冲突真实存在，列入待议。

### 2.7 亮点保留清单（重构不碰）

Apple 材质分层与双主题 token / focus ring 光环 / tabular-nums / 减弱动效 / 反馈层（Esc、焦点归还、滚动锁）/ 弹窗副本模式（防污染）/ 空态引导 + CTA / 套装下拉面板 / 双路径筛选与状态持久化 / 藏品页四列配平（64|96|211|minmax）/ ov-progress 撑满 / coll-panel 六列配平与双场景（弹窗+独立页）/ 止损容错三态 / 部位徽章固定宽列对齐。

## 三、重构方案（分批）

> 通用约束：不改类名与 DOM 结构断言、不改数据结构、不加外部依赖（保持离线可用）、每批交付附「双主题实拍 + 指标复测 + test 全绿」。

### 3.1 批次 0 · 缺陷修复（风险最低，无设计取向变化）—— ✅ 已实施（2026-10-15，见《圣遗物网页实现方案.md》§8.7）

1. **浅色语义色 AA 修复**：新增文字色 ink 变体（green/yellow/red/orange/purple 各一），只改**文字色**、底色调不变；覆盖徽章、评估汇总条、行内差异值、藏品数字、达成度百分比；主按钮浅色底加深（白字达标）。沿用「止损容错」深金 `#755d00` 的既有成例，实施时逐色采样至 ≥4.5:1
2. **移动端首页角色卡修复**：≤900px 改为三段堆叠（①名字+分数+状态徽章 ②有效词条 ③部位徽章换行），≥901px 维持现单行布局不变
3. **卫生清理**：`.rc-line` 残留 30px 右缩进；`.coll-bucket` 描边并入材质分层（去边框）
4. 验证：对比度采样复测（浅色全部 ≥4.5）+ 390px 实拍 + `test-dom` 全绿

### 3.2 批次 1 · 设计基座（字号下限）—— ✅ 已实施（2026-10-15，见《圣遗物网页实现方案.md》§8.8）

1. **字号下限 12px**：11px / 11.5px 全部并入 12px（首页部位徽章、藏品页全量、rolls、跳转按钮），以行高与内边距微调补偿，保持既有列宽配平不变；部位徽章 88px 固定宽复核容纳
2. 深色侧「藏品套装名」提亮（4.68 → ≥5.2）
3. 验证：字号直方图复测（<12px 归零）+ 藏品/首页布局 probe 复测 + 双主题实拍

### 3.3 批次 2 · 图标系统（内联 SVG）—— ✅ 已实施（2026-10-15，见《圣遗物网页实现方案.md》§8.9）

1. 手写内联 SVG 图标集（24 viewBox / 1.75px 线宽 / currentColor / 16·20px 两档），共 22 个：顶栏 7（评估/重塑/藏品/新建/导入/导出/外观）、详情操作 5（返回/配置/编辑/录入/删除）、状态 6（关闭/警告/信息/成功/失败/星标）、空态图形 4、部位 5（花/羽/沙/杯/冠）
2. 替换全部 emoji/字符图标（含空态彩色 emoji → 单色线性图形）；图标旁有文字的一律 aria-hidden，纯图标按钮保留 aria-label
3. 验证：全视图截图比对 + test-dom 全绿（类名不变）

### 3.4 批次 3 · 信息架构与交互—— ✅ 已实施（2026-10-15，见《圣遗物网页实现方案.md》§8.10；其中「顶栏低频动作收纳」后于批次 5 补做——§8.12）

1. 首页新增**搜索框**（按角色名过滤；与双路径筛选并存、纳入筛选状态持久化；`/` 聚焦快捷键可选）
2. 详情页 5 部位卡布局优化（方案见第四节决策 3）
3. 首页角色卡键盘可达（tabindex + Enter/Space）+ 全站 focus 走查
4. 藏品页窄屏降级（<1000px 不再横向滚动：折叠持有件摘要列或转卡片式）
5. 顶栏低频动作收纳（导入/导出并入「⋯」菜单，可选）
6. 待议项：部位卡点击编辑、红色语义统一（见决策 4）

### 3.5 批次 4 · 打磨池（按需选取）—— ✅ 已实施（2026-10-15：决策 4A 红色语义统一 + 双主题终检，见《圣遗物网页实现方案.md》§8.11；「顶栏收纳 / 视图方向感动效」经用户确认于批次 5 补做——§8.12）
